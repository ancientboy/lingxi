## 📷 图片上传功能修复

### 问题
前端上传图片后发送到 OpenClaw Gateway 时报错：`HTTP 400: {"error":{"message":"input: Invalid input","type":"invalid_request_error"}}`

### 根本原因
用户服务器上的 OpenClaw Gateway 配置中，responses API 的 `images.urlAllowlist` 没有包含图片上传域名 `lumeword.cn`，导致 Gateway 拒绝加载外部图片 URL。

### 解决方案
1. **修复用户服务器配置** (SSH 到 120.26.33.181)
   ```bash
   # 设置 images.urlAllowlist = ["*"]
   config.gateway.http.endpoints.responses.images.urlAllowlist = ["*"]
   ```

2. **修复部署脚本** (`/home/admin/.openclaw/workspace/lingxi-cloud/backend/routes/deploy.js`)
   - 添加 `"urlAllowlist": ["*"]` 到 images 配置
   - 确保新部署的用户服务器默认允许所有 URL

3. **正确的 OpenResponses API 格式** (根据官方文档)
   ```json
   {
     "model": "agent:main",
     "input": [
       {
         "type": "text",
         "text": "消息内容"
       },
       {
         "type": "input_image",
         "source": {
           "type": "url",
           "url": "https://lumeword.cn/uploads/xxx.jpg"
         }
       }
     ]
   }
   ```

### 测试验证
```bash
# 纯文本 - ✅ 成功
curl -X POST "http://120.26.33.181:18789/v1/responses" \
  -H "Authorization: Bearer <token>" \
  -d '{"model":"agent:main","input":"测试"}'

# 文本 + 图片 - ✅ 成功（配置 urlAllowlist 后）
curl -X POST "http://120.26.33.181:18789/v1/responses" \
  -H "Authorization: Bearer <token>" \
  -d '{"model":"agent:main","input":[{"type":"text","text":"测试"},{"type":"input_image","source":{"type":"url","url":"https://lumeword.cn/uploads/xxx.jpg"}}]}'
```

## 📝 经验教训

1. **配置合并优于覆盖** - 用户自定义配置应该保留，切换团队时只更新结构
2. **URL Allowlist 是常见陷阱** - 使用外部资源时必须配置 Gateway 的 allowlist
3. **官方文档是权威** - 遇到问题先查官方文档确认正确的 API 格式
4. **后端测试优先** - 修复后先用 curl 直接测试 API，确认通了再让前端测试
